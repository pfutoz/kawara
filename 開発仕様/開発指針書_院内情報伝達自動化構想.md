# 院内かわら版 開発指針書（基本構想と業務改革ロードマップ）

## 1. 策定の背景と現場の構造的課題

### 1.1 業務環境のギャップ（最大のボトルネック）
* **事務長の勤務体系**: 月・火・水・金（週4日勤務）
* **法人の稼働状況**: 医療法人小野会は24時間365日体制で稼働
* **現状の構造**:
  あらゆる連絡・依頼（設備故障、業者工事、日程調整、外部連絡）が事務長個人に集約される「手動のヒューマンルーター」状態となっている。
  事務長が不在となる「木曜日・土曜日・日曜日」に連絡が滞り、その前日（水曜夕方や金曜夕方）に事務長が出勤者をわざわざ探して口頭・手作業で伝達して回らざるを得ない。このため、伝達漏れ・うっかり忘れの精神的プレッシャーが極めて大きい。

### 1.2 現場スタッフと伝達手段のリアル
* **「既読＝理解」ではない問題**:
  LINEの既読がついたからといって、本当にその内容を理解しているか、立ち会い等の役割を果たせるかは分からない。**「1タップで了解や質問を返せる仕組み」**が現場には必要。
* **PC端末**: 詰所や各部署に共有PCはあるが、電子カルテ等の専用業務以外で自発的にブラウザを開いて「かわら版」を見に来るスタッフはほぼ皆無（事務員ですら見ない）。
* **紙媒体（印刷）**: 画面を印刷して手渡しするのが現状最も確実だが、事務長の手動印刷・配布負担が重すぎる。
* **LINEの受容性と限界**:
  * 院内への個人スマホ持ち込み制限や、「私用LINEを会社に教えたくない」スタッフが存在する。
  * スタッフのITリテラシーには差があり、**「PDFファイルを添付されても開けない・見ない」**。
  * 一方で、**「LINEのトーク画面に直接画像・カード形式で表示されるメッセージなら誰でも読む」**。
* **マルチチャネルの雑多な連絡（用務員的業務の集中）**:
  ウォシュレット故障、電球切れ、換気扇交換、水回り工事など、多種多様な連絡（LINE、手書き紙メモ、口頭、内線、外線電話）が事務長に丸投げされる体制が前任から定着してしまっている。

### 1.3 【突破口】LINE登録の大義名分：「災害時緊急安否確認・BCP連絡網の整備」
「普段の業務連絡のために私用LINEを登録してほしい」と頼むとプライベート侵害への反発が生じやすいが、**「医療機関としてのBCP（事業継続計画）・震災安否確認連絡網の義務化」**という公的名目を掲げることで、全職種・全スタッフが正当な手続きとして100%抵抗なく登録に応じる体制を作る。

### 1.4 本開発の究極の目的
* **事務長個人の負担軽減と「うっかり忘れ」の根絶**
* **事務長が不在の日（木・土・日）でも、現場が自律して安全に回る仕組みの構築**
* **将来、事務長が退職しても、後任が迷わず運用を引き継げる持続可能なシステム資産の確立**

## 2. システム設計思想（コアコンセプト）

```
【原則1】「見に来させる（プル型）」を捨て、「勝手に目に入る（プッシュ型・環境型）」にする
【原則2】「ファイルを開かせる（PDF等）」を捨て、「画面を開いた瞬間1秒で伝わる（Flex）」にする
【原則3】「既読待ち」を捨て、「1タップで了解・質問が返せる双方向アクション」を組み込む
【原則4】「過剰なアプリ開発」を避け、「Windows標準機能・軽量スクリプト」でスマートに解く
```

1. **グラフィカルなLINE Flex Message ✕ 1タップ意思表示**
   PDF添付や長文テキストを廃止し、トーク一覧から開いた瞬間に「日時・場所・工事内容・影響範囲（使用禁止・断水等）」がカラーバッジ付きで視覚的に直感理解できるカード型メッセージを送信。
   さらに、メッセージ下部のボタンを1タップするだけで**「👍 了解・対応します」「❓ 質問あり」「⚠️ 不在」**を返信できるようにする。
2. **脱・個人ID依存（グループ配信アプローチ）**
   個人のプライベートLINE登録の心理的ハードルおよびHTTPS環境構築のハードルを回避するため、LINE公式アカウントを各部署・全体の「連絡用グループ」に参加させ、グループ宛てに一斉プッシュ配信を行う。
3. **不在日（木・土日）を担保する自動引き継ぎ紙帳票**
   水曜・金曜に不在期間の予定を自動で束ねた「朝礼・回覧伝達シート」をワンクリック出力。日直・現場リーダーへの引き継ぎサイン欄を設け、責任を現場へ委譲する。
4. **現場ドア・壁貼り出しポスターの自動生成**
   設備修理や工事の情報を登録した際、現場にそのまま貼れるA4横の「特大注意喚起ポスター」を即座に印刷可能とし、当日事務長がいなくても患者・スタッフ・業者が迷わない環境を作る。

## 3. 機能アーキテクチャと詳細仕様

### 3.1 【中核機能1】LINE Flex Message ✕ 1タップ意思表示エンジン
* **概要**: `includes/line_helper.php` を拡張し、LINE Messaging API の Flex Message 形式に対応。
* **デザイン仕様**:
  * **ヘッダー**: カテゴリに応じたカラーリング（緊急＝赤、設備・工事＝オレンジ、重要＝青、一般＝グレー）
  * **タイトル**: 視認性の高い太字表記
  * **詳細ブロック**: 日時、場所、影響（赤太字）、業者名、立会者、対象部署
  * **フッターアクション（1タップ返答ボタン）**:
    * `[ 👍 了解しました・対応します ]`（メインボタン・緑）
    * `[ ❓ 質問・確認あり ]`（サブボタン・オレンジ）
    * `[ ⚠️ 不在・対応不可 ]`（サブボタン・グレー）
* **集計・可視化**:
  * スタッフがボタンをタップすると、かわら版DBに「了解ステータス」が即時記録される。
  * かわら版画面上で「誰が了解したか」「誰が質問ありと答えたか」が一覧表示され、事務長が前日に個別確認して回る手間をゼロにする。
* **災害安否確認モードへの即時転用**:
  * 地震等の有事の際には、配信ボタンが自動で「🟢 無事・出勤可」「🟡 軽傷・自宅待機」「🔴 被災・出勤不可」に切り替わり、全職員の安否確認が一瞬で集計可能。

### 3.2 【中核機能2】事務長不在日カバー機能（まとめ印刷＆日直引き継ぎ）
* **概要**: `index.php` および専用出力スクリプトにて、事務長が不在となる日（木曜、または土・日・月）の予定を一括集約して出力。
* **出力パターン**:
  1. **木曜不在カバーモード（水曜夕方出力）**: 翌木曜日の全予定・業者来院・重要事項を集約。
  2. **週末不在カバーモード（金曜夕方出力）**: 土・日・翌月曜の全予定を一括集約。
* **帳票構成**:
  * A4縦レイアウト
  * タイムライン形式の予定一覧
  * 現場リーダー／日直者確認サイン枠（「伝達受領印」「朝礼伝達済チェック」）

### 3.3 【中核機能3】設備・営繕・業者工事「A4現場貼り出しポスター」自動生成
* **概要**: お知らせ詳細・編集画面から「現場貼り出しポスター印刷」ボタンを押すことで、専用のCSS印刷用A4横レイアウトを即時展開。
* **フォーマット**:
  * 遠くからでも読める特大フォント（36pt〜48pt）
  * 「⚠️ 【工事・点検のお知らせ】」等の目立つアイキャッチ
  * 「○月○日(木) ○:○○〜○:○○」
  * 「場所：新館2F マイトイレ」
  * 「※ 工事中、このトイレは使用できません」
  * 「業者：〇〇設備（立会：〇〇）」

### 3.4 【中核機能4】Windows標準機能による自動印刷（PowerShell連携）
* **概要**: 専用のWindowsアプリを開発することなく、OS標準のPowerShellスクリプトとタスクスケジューラを組み合わせて特定ネットワークプリンタへ自動排紙。
* **動作フロー**:
  1. Windowsタスクスケジューラが毎朝定時（例: 朝07:00）にPowerShellスクリプトをトリガー。
  2. スクリプトがローカルApacheから「本日の伝達シートHTML/PDF」を取得。
  3. 各部署のネットワークプリンタ（IPまたは共有名指定）へサイレント印刷コマンドを発行。

## 5. 後任引き継ぎ・保守ガイドライン

### 5.1 設定情報の集約場所
* LINE API トークンおよび設定値: `includes/line_helper.php`
* データベース設定: 各PHP冒頭のPDO設定（将来的に `includes/db.php` に集約）
* 印刷テンプレート設定: `print_template/`（または各印刷用スクリプト内）

### 5.2 運用マニュアル要点（後任向け）
1. **日々の運用**: 基本的に「お知らせ作成（`create_post.php`）」で予定を入れるだけ。
2. **水曜・金曜の退勤前**: 「不在日まとめ印刷」ボタンを押し、印刷された紙を木曜・週末の当番日直に手渡す。
3. **設備修理・工事の連絡を受けたとき**: カテゴリを「設備・営繕」にして登録後、「ポスター印刷」で出てきた紙を該当箇所のドアに貼る。
4. **LINE配信**: 自動で1タップ返答ボタン付きカードが届き、スタッフの了解状況はかわら版画面でリアルタイムに確認できるため、個別電話や口頭確認は不要。
